# Hackathon Day: 9:00 AM Kickoff, 3:00 PM Presentations

This is a short event: **about 4–5 hours of effective build time** once kickoff and lunch/tour are included. Prioritize a stable MVP over a production system.

| Time (local) | Focus | Output |
|---|---|---|
| 9:00–9:15 | Welcome, select challenge, review rules | Team agreement |
| 9:15–9:40 | Run starter, choose roles, read test cases | App launches; roles assigned |
| 9:40–10:40 | UI improvements + clean data model | Form and result cards work |
| 10:40–11:55 | Provider integration or adapter + fee modeling | Search and comparisons tested |
| 12:00–1:00 | **Lunch + tour together** | Break and inspiration |
| 1:00–2:00 | Rewards logic + agent explanations | Cash/points recommendations |
| 2:00–2:35 | QA, cross-computer test, evidence | Tests pass, ZIP or repo ready |
| 2:35–2:55 | Submit, rehearse, final screenshots | Submission ready |
| **3:00 PM** | **Team presentations begin** | Live judge scenarios |

If event logistics shorten lunch or kickoff, shift blocks; **presentations stay at 3:00 PM**.

## Suggested 4-student roles
- **Frontend/UX:** search form, cards, mobile responsiveness, input errors.
- **Integrations:** provider adapters, source metadata, safe keys, price verification.
- **Rewards + agent:** totals, fees, cash vs award economics, recommendations.
- **QA + portability:** test cases, comparison evidence, environment setup, demo.

For a 3-student team, combine QA with frontend. Each person should test a change made by someone else.

## Freeze rule
Stop adding features 25 minutes before submissions, run the tests, do the cold-start test, and be ready for changing test inputs. An honest usable app beats an unfinished speculative agent.
